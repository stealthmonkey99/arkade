# Catcher — the SDK tutorial's finished cartridge

Fruit falls from the top of the panel. Walk under it with the stick to
catch it, dash (blue) for the ones you cannot walk to, and miss three
and the run is over. Four authored waves open a run and the endless
random game finishes it. Score goes on the cabinet's shared table.

**This directory is a destination, not a starting point.** It is the
finished state of the SDK's follow-along tutorial, checked in so you can
diff your own copy against it when a step does not behave:

- [Tutorial, part 1 — build the game](../docs/tutorial.md)
- [Part 2 — sprites and sound from scratch](../docs/tutorial-assets.md)
- [Part 3 — waves you draw by hand](../docs/tutorial-levels.md)
- [Part 4 — play, record, replay, ship](../docs/tutorial-debug.md)

If you want a *starting* point for your own game, copy
[`../template`](../template) instead — it is the minimal skeleton the
tutorial itself starts from.

## Why it lives here and not in the cartridges repo

Catcher is a teaching artifact, not a published game. A cartridge in the
[arkade-cartridges](https://github.com/stealthmonkey99/arkade-cartridges)
repo is part of the published collection: it gets a row in that repo's
manual library, `preflight -all` grades it, and it becomes a card on
arkade.build. A tutorial's worked example should not be published as a
game.

Sitting beside `sdk/template` keeps it fully buildable and fully tested
while joining none of that. The tutorial has *you* build in
`../my-cartridges/catcher/`, a cartridge library of your own beside the
engine checkout. From the engine checkout, `./arkade --cartridges
../my-cartridges/catcher` plays it in the terminal, and preflight finds it
given `ARKADE_CARTRIDGE_ROOTS=../my-cartridges`.

## Build, test, package

```sh
make build     # genlevelpack + manifestgen + tinygo + wasmfix -> catcher.wasm
make test      # rules, screens (hosttest), golden frames, determinism, ABI contracts
make rcart     # -> catcher.rcart, validated exactly as the cabinet would
```

From the repo root: `make sdk-tutorial` and `make sdk-tutorial-test`
(the latter also runs as part of `make test`).

`catcher.wasm` is committed, so the golden tests need no TinyGo.
`TestCatcherWasmMatchesSource` is what keeps the binary honest.

## Regenerating the assets

The sprite sheet and the sounds are committed, so a normal build uses
exactly the bytes that were reviewed. Regenerating them is deliberate:

```sh
make sheet     # assets/sprites/*.png -> assets/catcher.arkadesprite.png
make sfx       # Voice/Song literals  -> assets/*.wav    (sfxlib, musiclib)
make assets    # both
```

`levels_gen.go` is build output, like `manifest_gen.go`: every `make build`
regenerates it from `assets/*.arkadelevels` and leaves an up-to-date file alone.

The PNGs under `assets/sprites/` are the source of truth for the art —
open them in spritelab (import them at `arkade.build/dev/tools`, export them back)
and re-run `make sheet`. `catcher.png` is a three-cel animation strip;
its layout rides in a text chunk inside the PNG itself.

Catcher does not compile its art in as `ui.Sprite` literals. It
loads `assets/catcher.arkadesprite.png` from its own bundle at `Init`
(see `sprites.go`), so the packed sheet is data that ships in the
`.rcart` rather than Go that ships in the wasm. That is why this table has
a `sprites.go` you edit and no `sprites_gen.go` you must not.

`assets/waves.arkadelevels` is the source of truth for the authored waves —
hand-edit it or open it in levellab (import it at
`arkade.build/dev/tools`, export it back) and run `make build`. The
generator solves every wave before it writes anything, so a wave the
cartridge cannot play fails the build instead of the player.

## The files

| File | What it holds |
| --- | --- |
| `catcher.go` | The simulation, including the authored waves and the handover to the endless finale. Reaches for no host call, so `catcher_test.go` runs under plain `go test`. |
| `game.go` | The `cartlib.Game` implementation: the `sdk/fsm` screen machine, its entry hook, and the transitions between its five screens. |
| `input.go` | Input decode and dispatch, plus the standard hold-B exit. |
| `render.go` | Every screen, drawn through `sdk/ui`, plus the walk-cycle player. |
| `peripherals.go` | Sound, the 16×2 LCD, and the button lights. |
| `attract.go` | The cabinet's screensaver slot — silent by construction. |
| `sprites.go` | Lifts the bundle's sheet into `ui.Sprite`s at `Init`, and the walk cycle's step table. |
| `assets/catcher.arkadesprite.png` | Generated by `tools/gen-sheet`. Do not edit; edit the PNGs beside it. |
| `assets/waves.arkadelevels` | The four authored waves, hand-editable here or in levellab; compiled in, so not bundled. |
| `levels_gen.go` | Build output of `make build`. Do not edit; edit the pack. |
| `tools/gen-sheet/` | Packs `assets/sprites/*.png` into the one sheet the cartridge loads. |
| `tools/gen-sfx/` | Build-time audio synthesis, spectrum-asserted before it writes. |
| `tools/genlevels/` | Build-time wave validation: refuses an unplayable wave, derives its `par`. |
| `catcher_screens_test.go` | The screens against `sdk/cartlib/hosttest`'s fake cabinet: a run to game over, the quit overlay's push and pop. |
| `catcher_golden_test.go` | Golden frames, determinism, and the cabinet-wide contracts. |
