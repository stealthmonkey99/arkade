# Package ui

```go fragment
import "github.com/stealthmonkey99/arkade/sdk/ui"
```

Generated by `sdkdoc` from the package's doc comments, the same text `go doc` and pkg.go.dev show. Edit the Go source, then run `make sdk-docs`.

## Overview

Package ui is the rendering toolkit shared by the cabinet and every cartridge. Widgets draw onto an abstract [Canvas](ui.md#type-canvas), so one widget library produces identical pixels on a cartridge's framebuffer and on the cabinet's display.

The package compiles unchanged under TinyGo inside a cartridge, which binds all of it:

- No package init() and no computed package-level initializers: tables are compile-time literals TinyGo folds into static data, and setup that computes belongs in the cartridge's Init.
- No goroutines, channels, time, math/rand or wall clock: a frame is a pure function of its inputs.
- Avoid fmt and reflection (binary size).

Widgets are plain values: construct one (or fill in a struct literal) and call its Draw method with a [Canvas](ui.md#type-canvas) from the cartridge's render phase. Drawing never fails; geometry outside the canvas is clipped by [Canvas.Blend](ui.md#type-canvas). Stateful widgets such as [Menu](ui.md#type-menu), [NameEntry](ui.md#type-nameentry) and [HoldConfirm](ui.md#type-holdconfirm) are driven from Update with elapsed dtMicros and read back by the cartridge. Unless a doc says otherwise a call allocates nothing; the calls that do allocate say so and belong in Init.

Coordinates and sizes are in pixels, durations in microseconds.

## Constants

```go fragment
const (
	// ButtonDotSize is the disc's diameter in pixels, and the width of every
	// hint cell so a row does not shift when a slot changes control.
	ButtonDotSize = 7

	// StickHintSize is the width in pixels of the joystick hint, a left/right
	// chevron pair.
	StickHintSize = 7

	// HintRowHeight is the height in pixels of a hint row, matching the LED
	// font's line box.
	HintRowHeight = 8

```

```go fragment
const (
	HoldConfirmLCD1 = "QUIT GAME?"
	HoldConfirmLCD2 = "HOLD RED TO QUIT"
)
```

HoldConfirmLCD1 and HoldConfirmLCD2 are the standard 16x2 LCD legend for the overlay. Set them on the opening seat when it opens and re-assert the resumed screen's own text when it closes. Line 2 names the button by color because the cabinet's buttons are unlettered. The strings are compiled into each cartridge.

```go fragment
const (
	HoldRepeatDelayMicros    = 220_000
	HoldRepeatIntervalMicros = 120_000
)
```

The cabinet's hold-to-repeat cadence for a held stick direction, in microseconds: the press edge is the first step, then nothing for the delay, then one step per interval.

```go fragment
const (
	NameEntryHoldDelayMicros    = 350_000
	NameEntryHoldIntervalMicros = 90_000
)
```

NameEntryHoldDelayMicros and NameEntryHoldIntervalMicros are the hold schedule, in microseconds, a NameEntry scrolls its letters with: a held direction steps once after the delay and then once per interval. The delay is the cabinet's "did you mean to hold?" threshold, the same one a cartridge should use for any held-direction repeat; the interval suits a 26-letter ring and a shorter list may want a longer one.

## Variables

```go fragment
var (
	Highlight  = Color{255, 255, 255, 70}
	Shadow     = Color{0, 0, 0, 70}
	DarkShadow = Color{0, 0, 0, 100}
)
```

Highlight and Shadow are the semi-transparent overlay colors a beveled Border blends onto its top/left and bottom/right edges. DarkShadow is the deeper shadow BorderDarkEdge uses instead of Shadow.

```go fragment
var (
	Transparent = Color{}
	Black       = Color{0, 0, 0, 255}
	White       = Color{255, 255, 255, 255}
)
```

Common colors. Transparent is the zero value, so a zeroed Color is a no-op when blended.

```go fragment
var (
	ButtonGreen  = Color{R: 60, G: 220, B: 90, A: 255}   // joyA
	ButtonRed    = Color{R: 235, G: 80, B: 70, A: 255}   // joyB
	ButtonYellow = Color{R: 240, G: 200, B: 40, A: 255}  // joyC
	ButtonBlue   = Color{R: 70, G: 140, B: 255, A: 255}  // joyD
	ButtonAux    = Color{R: 255, G: 255, B: 255, A: 255} // joyAux1 and joyAux2, both white
)
```

The cabinet's button colours, as the panel draws them. The trailing names are the cartlib key names (KeyJoyA and friends), to help an author find the right colour; the buttons themselves carry no labels.

```go fragment
var (
	// NameEntryFilledColor paints a confirmed letter, and is also the
	// blink-off color of the active cell (never the dim empty color).
```

### type Attract

```go fragment
type Attract struct {
	// Phases is the ordered beat list. Build it once as a package-level
	// var, like [Menu].Items.
	Phases []AttractPhase
	// contains filtered or unexported fields
}
```

Attract drives the attract-mode phase cycle: an ordered list of timed beats (a score panel, then a silent demo, back to the panel, and so on) with the phase index, per-phase clock and per-transition setup handled for the cartridge. It does not decide what a phase draws or when a demo ends early, and it knows nothing about sound, LCDs, lamps or scores.

Phases is built once, in Init or as a package-level variable, not inside a render function. A phase with DurationMicros > 0 ends itself: [Attract.Update](ui.md#func-attract-update) advances to the next phase, wrapping past the last to Phases[0], once the phase clock reaches that duration. A phase with DurationMicros == 0 never times out; the cartridge calls [Attract.Next](ui.md#func-attract-next) or [Attract.Goto](ui.md#func-attract-goto) when it decides the phase is over, or to pick the next phase from data. Call Update from the update phase and [Attract.Draw](ui.md#func-attract-draw) from the render phase. Attract itself allocates nothing.

A phase's OnEnter runs once, synchronously, when the phase becomes current, including Phases[0] before the first transition (fired lazily by Update or Draw). It is the place to arm a demo's silent flag and swap in a local deterministic RNG before anything can play a sound or draw from RandomU64.

Attract is a plain value, not safe for concurrent use. Its zero value is ready to use once Phases is set. With no Phases, every method is a no-op.

#### func (*Attract) Draw

```go fragment
func (a *Attract) Draw(cv Canvas)
```

Draw fires Phases[0]'s OnEnter if it has not run yet, then calls the current phase's Draw with its elapsed clock. It does nothing with no Phases or a nil Draw.

#### func (*Attract) Elapsed

```go fragment
func (a *Attract) Elapsed() uint64
```

Elapsed reports the microseconds accumulated since the current phase began. A phase's Draw receives the same value; Elapsed serves drawing outside that callback, such as LCD text or button lights.

#### func (*Attract) Goto

```go fragment
func (a *Attract) Goto(i int)
```

Goto jumps to phase i, zeroing the clock and firing that phase's OnEnter. i is wrapped into range, so a negative i or one past the end is valid. Going to the current phase restarts it.

#### func (*Attract) Next

```go fragment
func (a *Attract) Next()
```

Next ends the current phase and moves to the next one in Phases, wrapping past the last to index 0. It zeroes the clock and fires the new phase's OnEnter. Use it for a cartridge-decided early exit that should behave like a timeout.

#### func (*Attract) Phase

```go fragment
func (a *Attract) Phase() int
```

Phase reports the current phase's index into Phases.

#### func (*Attract) Progress

```go fragment
func (a *Attract) Progress() float64
```

Progress reports the current phase's completion in [0, 1]: Elapsed divided by DurationMicros, clamped. It is 0 for a phase with DurationMicros == 0.

#### func (*Attract) Update

```go fragment
func (a *Attract) Update(dtMicros uint64) bool
```

Update advances the current phase's clock by dtMicros microseconds. If the phase has a nonzero DurationMicros that the clock has reached, it advances to the next phase (wrapping), fires its OnEnter and reports true. Call it once per frame with that frame's dtMicros.

A phase with DurationMicros == 0 still accumulates its clock but never advances here.

### type AttractPanel

```go fragment
type AttractPanel struct {
	X, Y, W, H int            // bounds, in pixels; nothing is drawn when W or H is not positive
	Title      string         // heading line in the accent color; empty omits it
	Top        AttractScore   // the #1 line
	Board      []AttractScore // ranks 2..N
	// Color is the board rows' text color; the zero value is White.
	Color Color
	// AccentColor is the Title and #1 row color; the zero value is Color.
	AccentColor Color
	// Trophy draws a gold cup in the left gutter of the #1 row and pushes
	// that row's text right. Board rows are indented to match only with Ranks.
	Trophy bool
	// TrophyColor overrides the trophy's gold; the zero value is gold.
	TrophyColor Color
	// T is the animation clock: the caller's accumulated dtMicros. Zero
	// means no clock and nothing animates.
	T uint64
	// Ranks draws each row's position number in a uniform left gutter.
	Ranks bool
	// RankColor overrides the rank numerals' color; the zero value is a
	// dimmed shade of the row's own color.
	RankColor Color
	// FirstRank is the number given to the first row drawn (the Top row, or
	// Board[0] when Top is empty). Zero means 1. Only meaningful with Ranks.
	FirstRank int
}
```

AttractPanel draws the standard score block onto a Canvas: a title, then the leaderboard, one rank per line, #1 first. Text is drawn in FontLED, plus a small procedural trophy; a cartridge that wants a game icon draws its own [Sprite](ui.md#type-sprite) beside the panel.

It draws only inside [X, X+W) x [Y, Y+H), never clears, holds no state between calls and is a pure function of the struct, so it can serve as an in-game HUD row as well as an attract screen. Call it from Draw. It allocates nothing.

##### Layout

Each present line sits attractRowH (10) pixels below the previous one: Title, then Top (trophy in the left gutter), then Board[0], Board[1], and so on. A nil Board omits the list. A zero-value Top (empty Name and zero Score) omits the #1 line; a Top or Board row with a score but no name draws the score alone. Rows are drawn in order and the first row that would fall outside [Y, Y+H) is skipped along with everything after it, so the bottom edge shows whole rows or nothing. Every score line has the shape `<name>  <score>` (two spaces between); first place is marked by AccentColor and the trophy, not by a different shape.

Text is drawn as given, with no case conversion.

##### Ranks

With Ranks set, every row carries its position number in a uniform left gutter. The gutter is measured once per Draw and fits the trophy or the widest numeral present, whichever is wider, plus a 2px gap. When Trophy is set the trophy stands in for the numeral on the Top row. FirstRank renumbers the stack for a caller that shows a window onto a longer board. With Ranks unset, the gutter is charged to the #1 row only.

##### Width

A row whose name, gutter and score fit in the width available is drawn statically. A row that does not fit depends on T:

- T == 0: the score is drawn in full and the name is cut to whole glyphs to fit, with no ellipsis.
- T != 0: the whole `<name>  <score>` strip scrolls inside the row, holding on the name, sliding to the score, holding there and sliding back, on a 3.5 second cycle.

Rows are measured independently, so only an overflowing row moves, and all moving rows share one phase. The title follows the same rule. All text is clipped to [X, X+W).

##### Clock

T is the caller's accumulated dtMicros; the panel never reads a clock of its own. Zero means "no clock", so a caller whose accumulator reads 0 on its first frame draws one truncated frame before the cycle starts.

#### func (AttractPanel) Draw

```go fragment
func (p AttractPanel) Draw(cv Canvas)
```

Draw composites the panel onto cv, top line first. Nothing is drawn when W or H is not positive.

### type Compositor

It owns no widgets, only a count and a current index: register the target count with [FocusManager.Reset](ui.md#func-focusmanager-reset) or [FocusManager.ResetGrid](ui.md#func-focusmanager-resetgrid), read [FocusManager.Focused](ui.md#func-focusmanager-focused) for the current index, and let the caller (such as [Menu](ui.md#type-menu)) decide what focused looks like. Only [NewFocusManager](ui.md#func-newfocusmanager) allocates, so call it from Init, or use a zero value and call Reset.

Targets form a row-major grid. Reset(count, FocusVertical) is one column and Reset(count, FocusHorizontal) is one row. Move clamps at the edges and never wraps; in a grid, a short last row clamps to the last valid target.

### type HeldDirs

```go fragment
type HeldDirs struct {
	// PulseMicros is the held credit granted per Pulse, in microseconds. 0
	// defaults to 250,000.
	PulseMicros uint64
	// contains filtered or unexported fields
}
```

HeldDirs tracks which directions are currently held, the level signal hold-to-repeat consumers need (name entry scrolling, rotation, paddle slew). It unifies the three ways hosts report a hold:

- Real HID buttons send KindKeydown and KindKeyup pairs.
- A joystick sends a position level that persists until its next record.
- The dev console keyboard sends only KindKeypress records, so a held arrow arrives as an auto-repeat pulse train; each pulse grants PulseMicros of held credit.

Feed every input record to [HeldDirs.Feed](ui.md#func-helddirs-feed), all kinds and before any keypress-only filter, call [HeldDirs.Update](ui.md#func-helddirs-update) once per frame, and read [HeldDirs.Held](ui.md#func-helddirs-held) or [HeldDirs.Current](ui.md#func-helddirs-current). Directions are tracked independently; Current collapses them to the most recently activated one. HeldDirs retains state across frames, so keep one per screen as a struct field or package variable. A zero value is ready to use, and no method allocates.

**Example**

```go
var held ui.HeldDirs
const dt = 100_000 // 100 ms per tick, in microseconds

// A real button reports both edges.
held.Feed(input.Record{Kind: input.KindKeydown, Key: input.KeyLeft})
held.Update(dt)
fmt.Println("left held:", held.Held(ui.DirLeft), "current is left:", held.Current() == ui.DirLeft)
held.Feed(input.Record{Kind: input.KindKeyup, Key: input.KeyLeft})
fmt.Println("after release:", held.Held(ui.DirLeft))

// A console keyboard only sends keypresses; each grants 250 ms of credit
// that decays with time.
held.Feed(input.Record{Kind: input.KindKeypress, Key: input.KeyRight, Flags: input.FlagVirtual})
held.Update(dt)
fmt.Println("right held:", held.Held(ui.DirRight))
held.Update(3 * dt)
fmt.Println("right held later:", held.Held(ui.DirRight))
```

Output:

```text
left held: true current is left: true
after release: false
right held: true
right held later: false
```

### type HoldConfirm

```go fragment
type HoldConfirm struct {
	// W, H are the overlay's canvas size in pixels. Zero or less defaults
	// to 64.
	W, H int
	// Title is the panel's headline. Empty defaults to "QUIT GAME?".
	Title string
	// HoldMicros is how long B must be held to confirm, in microseconds. Zero
	// defaults to
	// 1,000,000 (1 s), the standard hold.
	HoldMicros uint64
	// PulseMicros is the held credit, in microseconds, granted per
	// [HoldConfirm.Pulse]. Zero defaults to 600,000, long enough to bridge a terminal's key auto-repeat delay.
	PulseMicros uint64
	// QuarterTurns rotates the whole overlay by that many clockwise quarter
	// turns (0-3) on a square canvas, so a prompt on a seat-locked tabletop
	// board stands upright for the players. Leave 0 elsewhere. Avoid does
	// not apply to a rotated overlay.
	QuarterTurns int
	// contains filtered or unexported fields
}
```

HoldConfirm is the standard exit-confirmation overlay: press the quit key (B) to open it, then hold B to quit.

- Pressing B during play opens the overlay, and the cartridge stops ticking its sim while Active.
- The opening press must be released before the hold can begin, so a single long press cannot quit.
- Holding B fills a progress bar. At HoldMicros the widget confirms, blinks for 800 ms, and Update reports true once the blink has played and B is released. Releasing early drains the bar three times faster than it filled and keeps the overlay open.
- Any other press closes the overlay and resumes play.

Title, menu and game-over screens exit at once and do not use this widget. A qualifying name entry does use it, because a fumbled B would discard a score the player just earned. Opened over a [NameEntry](ui.md#type-nameentry), call [HoldConfirm.Avoid](ui.md#func-holdconfirm-avoid) with [NameEntry.LetterBand](ui.md#func-nameentry-letterband) right after [HoldConfirm.Open](ui.md#func-holdconfirm-open) so the panel does not cover the initials. A cartridge whose B returns to its title rather than exiting keeps that destination and retitles the prompt through Title, for example "END RUN?".

The overlay is a modal over the screen that raised it: model it as a screen pushed on top (`fsm.Machine.Push` and `Pop`). Popping re-enters the covered screen, which must re-assert its own LCD text and lamps; peripherals are never restored for you.

HoldConfirm keeps state across frames, so hold one as a field. A zero value is ready to use, and none of its methods allocate.

##### Feeding input

While Active, pass every input record to [HoldConfirm.Feed](ui.md#func-holdconfirm-feed), keydown and keyup included. Route it before any keypress-only filter, or the hold never arms on a real pad:

```go fragment
if confirm.Active() {
    if !confirm.Feed(r) && r.IsPress() {
        confirm.Close() // any other press cancels
    }
    return
}
```

Open the overlay from the playing screen's quit press with [HoldConfirm.Open](ui.md#func-holdconfirm-open) followed by Feed of that same record. Each frame while Active, call [HoldConfirm.Update](ui.md#func-holdconfirm-update) with dtMicros and `cartlib.Exit` when it reports true. Call [HoldConfirm.Draw](ui.md#func-holdconfirm-draw) last so the overlay composites over the frozen game.

Real buttons send keydown and keyup, and the first keyup after Open arms the hold. The dev console keyboard sends only keypresses, so each virtual keypress grants PulseMicros of held credit and the credit expiring stands in for the release.

HoldConfirmLCD1 and HoldConfirmLCD2 are the matching per-seat LCD legend.

**Example**

```go
var confirm ui.HoldConfirm
const dt = 100_000 // 100 ms per tick, in microseconds

down := input.Record{Kind: input.KindKeydown, Key: input.KeyJoyB}
up := input.Record{Kind: input.KindKeyup, Key: input.KeyJoyB}

// B pressed during play opens the overlay; the opening press must be
// released before the hold can begin.
confirm.Open()
confirm.Feed(down)
confirm.Feed(up)

// Hold B: the bar fills over HoldMicros (one second by default).
confirm.Feed(down)
for i := 0; i < 5; i++ {
	confirm.Update(dt)
}
fmt.Printf("progress %.1f\n", confirm.Progress())
for i := 0; i < 5; i++ {
	confirm.Update(dt)
}
fmt.Println("confirmed", confirm.Confirmed())

// Release B; once the confirmation blink has played Update reports true.
confirm.Feed(up)
quit := false
for i := 0; i < 10 && !quit; i++ {
	quit = confirm.Update(dt)
}
fmt.Println("quit", quit)
```

Output:

```text
progress 0.5
confirmed true
quit true
```

Multiples of 90 use exact integer arithmetic. Other angles use math.Sin and math.Cos, which are not guaranteed bit-identical between TinyGo and host Go, so build the line when the angle changes and Draw the resulting value each frame rather than calling LineFromAngle per frame.


### type Mask

```go fragment
type Mask struct {
	W, H int      // size in pixels; W must not exceed 64
	Rows []uint64 // one row per entry, bit x set when pixel x is collidable
}
```

Mask is a bit-per-pixel collision mask: Rows[y] bit x (1<<x) is set when local pixel (x, y) is collidable. W is at most 64, the uint64 row width. Rows holds one entry per row of H; a row past len(Rows) has no collidable pixels, so a Mask built with fewer rows than H is a shorter shape, not an invalid one. A Mask can back a [Sprite](ui.md#type-sprite) or stand alone as a shape, such as a round hitbox for a procedurally drawn character.

#### func OpaqueMask

```go fragment
func OpaqueMask(w, h int, pix []byte) Mask
```

OpaqueMask builds the collision mask of w×h straight-alpha RGBA pixels (row-major, 4 bytes each): a pixel is collidable exactly when its alpha is 255. This is the rule behind every [Sprite.Mask](ui.md#type-sprite) cartlib lifts from a bundled sheet, and the one to follow when building a Sprite by hand. w must be at most 64 and pix at least w*h*4 bytes long, or OpaqueMask panics. It allocates the rows, so call it from Init, not per frame.

#### func (*Mask) At

```go fragment
func (m *Mask) At(x, y int) bool
```

At reports whether local pixel (x, y) is collidable. Out-of-bounds is simply false, so callers can probe without pre-clamping. It allocates nothing.

#### func (*Mask) Overlaps

```go fragment
func (m *Mask) Overlaps(mx, my int, o *Mask, ox, oy int) bool
```

Overlaps reports whether any collidable pixel of m placed at (mx, my) coincides with a collidable pixel of o placed at (ox, oy), with positions in pixels. It allocates nothing, so it is safe to call every Update.

### type NameEntry

```go fragment
type NameEntry struct {
	X, Y int // top-left of the letter row, in pixels
	// contains filtered or unexported fields
}
```

NameEntry is the cabinet-standard high-score name entry: classic arcade slot cycling over a fixed number of letter slots (DefaultNameEntryMaxLen by default) plus a trailing OK cell, so a name can be submitted with directions and one activate button alone.

##### Input

[NameEntry.Move](ui.md#func-nameentry-move) is a level call: pass the currently held direction every frame ([DirNone](ui.md#constants) when nothing is pressed). NameEntry detects the press edge itself and cycles or moves the cursor once on that edge. Holding Up or Down then auto-repeats through Update; Left and Right do not repeat.

[NameEntry.Do](ui.md#func-nameentry-do) is an edge call: call it once per newly pressed action button, not every frame it is held. Read the result with [NameEntry.Done](ui.md#func-nameentry-done) and [NameEntry.Name](ui.md#func-nameentry-name).

##### Timing

[NameEntry.Update](ui.md#func-nameentry-update) accumulates the widget's own clock from dtMicros, which drives the cursor blink (500 ms period) and the hold-to-scroll repeat (350 ms delay, then 90 ms interval). Call it every tick while the entry is active.

##### Layout

Cells are 6px wide, the widest glyph in the charset, so the row is monospaced. Each glyph is centered in its cell. Confirmed letters draw white, empty slots a dim gray underscore and the OK cell a green checkmark; the cell under the cursor blinks yellow and white, never the dim empty color. Colors are the exported NameEntry*Color variables.

Construction and configuration ([NewNameEntry](ui.md#func-newnameentry), [NameEntry.SetName](ui.md#func-nameentry-setname), [NameEntry.SetRecents](ui.md#func-nameentry-setrecents)) allocate and belong in Init; Move, Do, Update and Draw do not.

##### Recent names

SetRecents offers up to NameEntryMaxRecents names. They hang off the bottom of the first slot's cycling ring: at slot 0, pressing Down past the blank walks the list instead of wrapping to '9', and each name previews across the whole row. Activate takes the previewed name and parks on OK, Up backs out to the blank with the typed letters restored, and continuing Down past the list resumes the charset at '9'. The next name down is drawn faded under the row as the only hint the list exists.

**Example**

```go
entry := ui.NewNameEntry(0, 0, 3) // in Init: three letter slots
const dt = 16_667                 // one 60 Hz tick, in microseconds

// Move takes the held direction every tick; Do takes each fresh press.
tap := func(dir ui.Direction) {
	entry.Move(dir)
	entry.Update(dt)
	entry.Move(ui.DirNone)
	entry.Update(dt)
}

tap(ui.DirUp) // blank -> A
entry.Do(ui.ActionActivate)
tap(ui.DirUp) // blank -> A
tap(ui.DirUp) // A -> B
entry.Do(ui.ActionActivate)
fmt.Printf("typed %q, done %v\n", entry.Name(), entry.Done())

entry.Do(ui.ActionActivate) // empty third slot jumps to OK
entry.Do(ui.ActionActivate) // Activate on OK submits
fmt.Printf("submitted %q, done %v\n", entry.Name(), entry.Done())
```

Output:

```text
typed "AB", done false
submitted "AB", done true
```

#### func NewNameEntry

```go fragment
func NewNameEntry(x, y, maxLen int) *NameEntry
```

NewNameEntry builds a blank NameEntry with its top-left at (x, y) pixels and maxLen letter slots; maxLen <= 0 means [DefaultNameEntryMaxLen](ui.md#constants). Call it from Init: it allocates.

#### func (*NameEntry) Do

```go fragment
func (n *NameEntry) Do(act Action)
```

Do fires one edge-triggered action; call it once per newly pressed button. [ActionActivate](ui.md#type-action) on a filled slot confirms it and advances one cell (off the last slot onto OK), on an empty slot jumps to the OK cell, and on the OK cell submits. During a recent-name preview it accepts the name and jumps to OK. [ActionErase](ui.md#type-action) clears the current slot and moves left, or just moves left on an empty slot or the OK cell; during a preview it backs out to the blank with the typed letters restored. [ActionBack](ui.md#type-action) and every other action are ignored, leaving B free for the host's quit handling. Everything is ignored once Done.

#### func (*NameEntry) Done

```go fragment
func (n *NameEntry) Done() bool
```

Done reports whether the player has submitted with [ActionActivate](ui.md#type-action) on the OK cell. Once true the widget ignores input until [NameEntry.Reset](ui.md#func-nameentry-reset).

#### func (*NameEntry) Draw

```go fragment
func (n *NameEntry) Draw(cv Canvas)
```

Draw composites the letter slots, the OK cell and, when recents are offered, the faded peek line under the row.

#### func (*NameEntry) LetterBand

```go fragment

```

LetterBand returns the canvas rows the letter slots and OK cell occupy: rows y through y+rows-1 that the letter slots and OK cell occupy, in pixels. The faded recent-name line below them is not included. Pass it to [HoldConfirm.Avoid](ui.md#func-holdconfirm-avoid) when the quit overlay opens over the entry.

#### func (*NameEntry) Move

```go fragment
func (n *NameEntry) Move(dir Direction)
```

Move reports the currently held direction; call it every frame with [DirNone](ui.md#constants) when nothing is pressed. On the press edge, Up and Down cycle the focused slot (auto-repeating through Update while held) and Left and Right move the cursor across all cells including OK, clamped, without repeating. Ignored once Done.

#### func (*NameEntry) Name

```go fragment
func (n *NameEntry) Name() string
```

Name returns the contents with trailing blanks removed, valid mid-entry and after Done. An all-blank entry returns "".

#### func (*NameEntry) Reset

```go fragment
func (n *NameEntry) Reset()
```

Reset returns the widget to its starting state: the prefill with the cursor on OK when one is set, otherwise blank at slot 0. The prefill is unchanged.

#### func (*NameEntry) SetName

```go fragment
func (n *NameEntry) SetName(name string)
```

SetName sets the prefill and resets the widget to it. The name is uppercased, stripped of anything outside A-Z, 0-9 and space, trimmed of trailing spaces and cut to the slot count. A non-empty prefill starts the cursor on OK so a returning player confirms with one [NameEntry.Do](ui.md#func-nameentry-do) of [ActionActivate](ui.md#type-action). An empty name clears the prefill and restores the blank start at slot 0. It allocates, so call it from Init, not per frame.

#### func (*NameEntry) SetRecents

```go fragment
func (n *NameEntry) SetRecents(names []string)
```

SetRecents offers up to [NameEntryMaxRecents](ui.md#constants) recently used names below the charset; see the type doc. Names are sanitized and truncated like a prefill, blanks and duplicates are dropped, and names past the fifth survivor are ignored. With no surviving names the widget behaves as if recents were never offered. Call it from Init, alongside SetName.

#### func (*NameEntry) Update

```go fragment
func (n *NameEntry) Update(dtMicros uint64)
```

Update advances the blink phase and the hold-to-scroll auto-repeat by dtMicros microseconds. Call it every tick from Update while the entry is active.

### type Sprite
