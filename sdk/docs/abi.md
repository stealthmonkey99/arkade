# ABI reference

The cartridge ABI is the entire portability contract of Årkade: one
`.wasm` module, two hosts. The cabinet embeds
[wazero](https://github.com/tetratelabs/wazero) (`internal/cartridge/wasm`);
the browser is itself a wasm runtime (the arkade.build player).
Everything on this page is what both hosts implement byte-for-byte.

**Current version: 1.** The number identifies the calling convention,
not the set of imports: a new host import is additive and never moves
it, because a module resolves only the imports it declares. It moves
only when a cartridge built against the old number would fail on the
new host, and hosts then state the range they accept. A cartridge
outside that range fails with one clear "unsupported ABI version" error
instead of a confusing crash.

Most authors never touch this layer: [cartlib](cartlib.md) wraps all
of it. Read this page when you're debugging at the boundary, writing a
host, targeting the ABI from another language (Rust/Zig/C work day
one — plain `extern` imports/exports), or deciding whether a new
capability may exist at all. This page is the current contract.

## Design rules

1. **No WASI in the contract.** Time, randomness, logging, storage,
   and I/O all arrive through imports in the `"arkade"` module. A
   cartridge that only uses the ABI runs anywhere. (Toolchains may
   still *emit* incidental WASI imports; hosts provide exactly the
   four TinyGo needs — `clock_time_get` and `random_get` redirect to
   engine time and RNG, `fd_write` to fds 1 and 2 logs (any other fd
   is `EBADF`), `proc_exit` is an inert no-op. Any other WASI import
   is unregistered, so the cartridge fails to instantiate.)
2. **Determinism carries over.** Cartridges never see a wall clock or
   an OS RNG — see [Determinism](#determinism) below.
3. **Sandbox by construction.** No filesystem, no sockets, no spawn.
   Storage and scores are namespaced by cartridge slug *implicitly* —
   no API even exists to name another game's data.
4. **The framebuffer blit is the fast path.** One `host_blit` per
   frame beats 4,096 `host_draw_pixel` crossings.
5. **Handles, not pointers.** Sprites and sounds are registered once
   and referred to by opaque `u32` ids the host owns. Strings/bytes
   cross the boundary as (pointer, length) pairs into guest linear
   memory; the host never retains a guest pointer past the call.

<!-- /sdkdoc:exports -->

- The eight required exports fail instantiation if missing.
- `cart_init`'s `cols, rows` are always 64, 64; cartlib does not pass
  them to `Game.Init`, which instead receives the `*cartlib.Setup` that
  scopes asset loads, channel binds and glyph definitions to this call.
- `cart_alloc` is how the host writes into guest memory without
  guessing at the allocator: before each `cart_handle_input` it calls
  `cart_alloc`, writes the records, then calls
  `cart_handle_input(ptr, len)`. Returning a reused static buffer is
  fine and typical.
- `cart_update`'s `dtMicros` is the **per-tick delta**, not a running
  total.
- `cart_render` **may be called before the first `cart_update`** —
  a cartridge must render a valid frame from post-`cart_init` state.
- `cart_attract` is cabinet-only (the browser is one-cart-per-page):
  called each frame while the idle screensaver shows this cartridge's
  slot. Draw over the engine's starfield — transparent pixels show the
  stars — and optionally set LCDs/lights. No export ⇒ the engine's
  default showcase.
- **TinyGo note**: TinyGo cannot emit the genuine two-result
  `cart_manifest` export; the SDK build's mandatory `wasmfix`
  post-pass rewrites it. Hosts always see the two-result signature.

### Runtime boot

If a module exports `_start` (a TinyGo `-target=wasi` build), the host
calls it **exactly once at instantiation**, before `cart_abi_version`.
This exists purely to initialize TinyGo's `-gc=leaking` allocator
bookkeeping — skipping it left steadily-allocating cartridges with
silently corrupted memory. It is *not* a license to put logic in
`main`/`init`: the SDK convention (empty `main`, setup in `cart_init`)
stands. During the boot call the WASI stub's `random_get` returns a
fixed pattern (`0xA5 ^ i`) so the deterministic RNG stream is never
consumed, and `proc_exit(0)` is a silent no-op. Modules without
`_start` (e.g. a wasi-sdk reactor build) are not booted at all.

violation is **warn-and-no-op** — a bad cartridge may never take down
the host.

### Wire encodings

The cartlib wrappers speak Go values; another language targets the
import itself, so these are the encodings behind the signatures above:

- `host_blit` takes raw interleaved R,G,B,A bytes, row-major, with
  `length == 64*64*4` (bytes, not packed u32 words). Its full-frame copy
  overwrites anything `host_draw_*`, `host_fill_rect` or
  `host_draw_cel` drew, which is why cartlib wraps none of them.
- Every handle (`host_load_sound`, `host_load_sprite`, `host_load_sheet`,
  `host_sheet_cel`) is a `u32` whose 0 means failure; every call on
  handle 0 is a no-op.
- `host_play_sound`'s `loopCount` is the total number of plays, 0 and 1
  both meaning once, and `0xFFFFFFFF` loops until stopped.
- `host_cel_info` writes `w, h, anchorX, anchorY` as four little-endian
  `u16` and returns 1; `host_cel_read` writes straight-alpha RGBA and
  returns the bytes written.
- `host_storage_read` returns the bytes written, 0 when the key is
  absent; `host_storage_write` has no result, and an illegal key or an
  oversized value is dropped whole.
- `host_now_micros` is the engine clock, never wall time;
  `host_random_u64` is the engine-seeded RNG. `host_log`'s level is 0
  debug, 1 info, 2 warn, 3 error.
- `host_score_submit` returns the 1-based rank, 0 when the score did not
  place; `host_score_read` writes the `i64` score little-endian followed
  by the name; `host_score_qualifies` returns 0 or 1.
- The recent names are per physical seat and keep two memories:
  `host_recent_name_get` is the auto-suggest prefill (RAM only, one-hour
  lifetime on the engine clock), `host_recent_name_at` walks that seat's
  five-deep most-recently-used list (persisted) and returns 0 past its
  end, and `host_recent_name_note` feeds both.
- `host_push_player_strategy`'s `kind` is 0 any, 1 solo, 2 vs-AI,
  3 turn-based; `host_switch_player`'s `mode` is 0 toggle, 1 to-primary,
  2 to-secondary. `host_set_raw_directions` takes 0 or 1 and lasts until
  this instance unloads.
- `host_input_bind`'s `kind` is 0 button, 1 axis, 2 delta, 3 blob; it
  succeeds during `cart_init` only and returns -1 for a channel not
  offered, and every reader on -1 reads zero. Axes are in the `int16`
  range, deltas count since the last `cart_update`, and
  `host_input_blob` copies all or nothing. `host_output_bind` is
  reserved and always returns -1; `host_output_set` is a no-op.
- `host_define_lcd_glyph` returns 1 accepted, 0 rejected;
  `host_lights_play` returns 1 when a cue is now playing.

### Semantics worth pinning

**Scores are an import, not just storage** so the qualification policy
(top ten, tie-with-10th does not qualify, equal scores rank after
existing equals) lives once host-side and every game shares it — and
so the shell/attract can read any game's table by slug from outside
the game.

**Player strategy is an affordance, not a guarantee.** A push alone is
inert until `host_lock_player_strategy`. The browser host ports the
engine's strategies, gating and rotation included, but neither host
gates a keyboard record — a two-player cartridge must still demux on
the input record's `player` byte.

**Peripheral `player` argument**: `-1` addresses both sides, `0`/`1`
one side; anything else is rejected. cartlib takes a `cartlib.Seat`
instead and maps `SeatBoth` to `-1`; `SeatNone`, what a seatless record
carries, never reaches the host. `host_set_text` lines are UTF-8,
≤64 bytes each on the wire (the LCD clips at 16 runes downstream —
the headroom is for multi-byte glyphs like `♥`).

**`host_set_button_lights` mask bits** (the same MCP23017-pin-offset
order every hardware caller uses — hosts must vendor these six names
in this order):

| bit | button |
| --- | --- |
| 0 | `joya` |
| 1 | `joyb` |
| 2 | `joyc` |
| 3 | `joyd` |
| 4 | `joyaux1` |
| 5 | `joyaux2` |

`only != 0` builds a full six-entry table (every unmentioned button
explicitly off); `only == 0` merges — set bits turn on, everything
else keeps its state.

A lamp FLOURISH — a pulse, a chase — does not have to be written as a
timer in `Update`. `host_lights_play`/`host_lights_stop` walk a
`.arkadelights.json` the bundle carries, on the tick; a
`host_set_button_lights` call always takes the lamps back. See
[Lamp sequence reference](reference-lights.md).

**`host_set_lamp_levels` packing.** Each lamp runs at a level 0..15
(0 dark, 15 the same as `host_set_button_lights` lighting it) packed
four bits per lamp into `levels`, low nibble first, in the same lamp
order as the mask table above; bits 24..31 are unused:

| bits | lamp |
| --- | --- |
| 0–3 | `joya` |
| 4–7 | `joyb` |
| 8–11 | `joyc` |
| 12–15 | `joyd` |
| 16–19 | `joyaux1` |
| 20–23 | `joyaux2` |

`touch` is a one-bit-per-lamp mask in the same order as the mask
table (not the nibble table above) — bit *i* addresses lamp *i*; a
lamp outside `touch` keeps its current level and any fade already
running on it. `touch == 0` is a complete no-op: no write, and — alone
among the lamp calls — no sequence stop. `fade_ms` is milliseconds, 0
for an instant write, clamped to 10000. Semantics: [Levels and fades
from code](reference-lights.md#levels-and-fades-from-code).

**`host_define_lcd_glyph` — cartridge-defined LCD glyphs.** The panel is
an HD44780: it draws ASCII from a mask ROM, and anything else must be
uploaded as a 5×8 bitmap into one of eight CGRAM slots. The engine ships
a palette of those bitmaps; this import lets a cartridge bring runes the
palette lacks, without an engine change and a cabinet rebuild.

The eight pixel rows are **packed into the `u64`** rather than passed as
a `(ptr, len)` pair: 8 rows × 8 bits is exactly 64, so a whole glyph
crosses as one wasm value — no guest pointer to bounds-check, nothing to
copy, and nothing for a guest SDK to allocate. Row 0 (the **top** row) is
the low byte, row 7 the high byte; only the low 5 bits of each row are
used, **bit 4 being the leftmost column**, and hosts mask the other three
so a careless guest still draws identically everywhere.

Returns 0, with a sandbox warning, when:

| Rejection | Why |
| --- | --- |
| `codepoint < 0x80` | the chip's own ROM draws ASCII; redefining a letter — or a space — would burn a CGRAM slot on every line containing it |
| surrogate, noncharacter, or `> 0x10FFFF` | not a code point |
| an emoji: `0x1F000`–`0x1FFFF`, the BMP code points with `Emoji_Presentation=Yes` (⚡ ⭐ ✅ ❌ …), variation selectors `0xFE00`–`0xFE0F`, the zero-width joiner `0x200D` | a glyph rune must be a plain, single-width, monochrome character; a terminal draws an emoji in colour and two cells wide, so no surface that shows LCD text could draw it evenly. ♥ ☺ ✔ and the other text-presentation symbols stay allowed — the engine's own table lives there |
| East Asian wide: `0x1100`–`0x115F`, `0x2E80`–`0xA4CF`, `0xAC00`–`0xD7A3`, `0xF900`–`0xFAFF`, `0xFE30`–`0xFE4F`, `0xFF00`–`0xFF60`, `0xFFE0`–`0xFFE6`, and everything from `0x20000` up | two cells wide by definition. The table is `internal/lcdrune` on the cabinet and `lcdRune.ts` in the browser host, mirrored line for line |
| table already holds 32 distinct runes | the per-cartridge cap; *re*defining a rune already in the table always succeeds and does not grow it |

The return value is a pure function of the arguments and the cartridge's
own table — **not** of whether the host has an LCD at all — so a
cartridge cannot branch on which host it is running under. A host with
nowhere to draw simply has nowhere to draw.

Semantics:

- A definition **shadows** the engine palette for that cartridge only.
  On the cabinet the operator's glyphlab preview overlay
  (the dashboard's `/api/preview/lcd` route, `docs/DASHBOARD.md`)
  still sits above both.
- Definitions are **cleared at `cart_teardown`**, after the export
  returns, so a farewell `host_set_text` still draws them and nothing
  survives into the shell, the attract loop or the next cartridge.
- `cart_init` is the documented place to call it. Later calls are
  honored and take effect on the next redraw.
- **The 8-slot budget is unchanged** and is now shared between the two
  sources. A screen wanting a ninth distinct custom rune evicts the
  least-recently-used and renders `?`, exactly as before. 32 is a table
  cap, not a drawing budget.

**`host_exit` is request-only**: it sets a pending flag the engine
applies *between* ticks, so calling it from inside any guest call is
safe by construction — nothing is torn down while cartridge code is on
the stack. The browser host mirrors this with an `onExit` callback
invoked after the current fixed-step iteration.

**Quit-key ownership**: *declaring* the `host_exit` import is the
cartridge's opt-in to owning its quit keys. The cabinet detects the
import at compile time and routes `q`/`escape`/`joyb` presses to the
cartridge instead of the engine's default quit-to-shell map — so the
cartridge can run a confirm-exit flow and call `host_exit` when the
player means it. A cartridge that never declares the import keeps the
default behavior, so no cartridge can become un-exitable. (cartlib
always declares it, and so calls `host_exit` itself on every quit-key
press unless the game implements `cartlib.QuitOwner`.)

## Input records

`cart_handle_input` receives 0..n fixed **8-byte** records:

| offset | field | notes |
| --- | --- | --- |
| 0 | kind | 0 keydown, 1 keyup, 2 keypress, 3 joystick |
| 1 | key | key ordinal (table below) |
| 2 | player | 1 or 2 — the **pairing slot**; the host never emits 0, and keyboard or system events read as 1 |
| 3 | joy | 0 center, 1..8 = N, NE, E, SE, S, SW, W, NW |
| 4 | source | 0 keyboard, 1 controller |
| 5 | physical | cabinet **port**, or `0xFF` = none |
| 6 | index | controller slot, or `0xFF` = none |
| 7 | flags | bit 0 = virtual source, bit 1 = shift held |

- **Press-record convention**: cabinet controllers emit a
  keydown+keypress *pair* per physical press (and keyup on release);
  the browser host speaks the same dialect. **Keypress (kind 2) is the
  canonical act-once record** — a cartridge that also acts on keydown
  double-fires on hardware.
- **`player` ≠ `physical`**: pairing slot vs cabinet port. They
  diverge when someone picks up the other controller. Address
  peripherals by `physical`, decide gameplay by `player`. `physical`
  and `index` are meaningless for keyboard sources.
- **The virtual flag is load-bearing**: a real stick emits both a
  joystick record and a synthetic (non-virtual) direction keypress per
  push. Act once by gating:
  `kind == joystick || flags & virtual != 0`.
- **Rotation-aware direction remapping happens host-side** — the
  cabinet remaps by seat mount + display orientation before the
  cartridge ever sees a record; the browser host remaps the same way
  for the orientation its strategy port draws.
  Cartridges see logical directions only (unless they opt out via
  `rawDirections` / `host_set_raw_directions`).

**Key ordinals** (canonical table: `internal/cartridge/wasm/keys.go`;
cartlib and the web host each carry a pinned transcription):

```text
0 brightness   7 down        14 joyc      21 joyaux2
1 rotate       8 left        15 joyd      22 joyaux3
2 quit         9 right       16 l1        23 joyaux4
3 escape      10 home        17 r1        24 select
4 enter       11 end         18 l2        25 start
5 space       12 joya        19 r2        26 turbo
6 up          13 joyb        20 joyaux1   27 clear

28 mic.whistle   29 mic.clap   30 mic.blow   31..38 mic.cue0..mic.cue7
```

The microphone keys arrive as keypresses with player 1, physical `0xFF`
and the virtual flag set, and only to a cartridge whose manifest
declares the `mic` capability
([microphone reference](reference-mic.md#what-a-cartridge-receives)).

## Runtime manifest

`cart_manifest()` returns a small JSON object:

```json
{
  "abi": 1,
  "slug": "snake",
  "name": "Snake",
  "version": "1.0.0",
  "players": [1, 2],
  "icon": "assets/sprites/icon.png"
}
```

`slug` is the storage/score namespace and must match the `.rcart`
filename stem. `rawDirections` (bool, default false) opts the whole
cartridge out of the host's direction remap — for egocentric control
schemes only; `host_set_raw_directions` scopes it at runtime instead,
and the override dies with the instance. This runtime manifest is
distinct from the bundle's `manifest.json` (the registry metadata
file) and generated from it, so the shared fields (`slug`, `version`,
`rawDirections`…) always agree; see
[Manifests & packaging](packaging.md).

## Determinism

The load-bearing invariant: **everything observable in a frame is a
pure function of `(dt_micros, input records, host_random_u64 draws)`.**

- `host_now_micros` is engine time (a manual clock in tests);
  `host_random_u64` is the engine's seeded RNG. There is no other
  clock and no other entropy, by construction.
- This is the test for whether a proposed capability may live
  guest-side at all: if it would make a frame depend on anything else,
  it must be mediated by a host import or it breaks replay.
- What it buys: golden tests replay a scripted run and diff frames
  pixel-for-pixel; the **same `.wasm` with the same script on both
  hosts** produces byte-identical frames (each cartridge's
  `*_golden_test.go` through `carttest` on the cabinet side, and the
  browser host checked against the same golden files); a future leaderboard can verify a submitted score by
  replaying its input log.
- Cartridge-side corollaries (enforced by the golden tests): no wall
  clocks, no OS RNG, no goroutines, and no libm transcendentals on
  observable paths (plain float64 arithmetic is IEEE-754-identical
  across toolchains; `sin`/`cos`/`pow` implementations are not).
- The parity that is enforced is cabinet-host vs browser-host on the
  same binary — deliberately *not* port vs original: an RNG wrapper
  can't reproduce another library's exact draw sequence, so a game
  ported from elsewhere re-records its goldens once.

## Sandbox caps

Enforced identically by both hosts (and by `rcartpack` at pack time
for the bundle-level ones); all warn-and-no-op:

| Surface | Cap |
| --- | --- |
| `host_log` message | 4096 B |
| storage key | 256 B, charset `[A-Za-z0-9_.-]+` |
| storage value | 64 KiB |
| score / recent name | 64 B |
| sprite PNG | 1 MiB |
| sound path | 512 B |
| LCD line | 64 B |
| cartridge LCD glyphs | 32 definitions (8 drawn at once, per screen) |
| input batch | 1024 records |
| `game.wasm` in a bundle | 8 MiB |
| `manifest.json` in a bundle | 1 MiB |
| whole `.rcart`, uncompressed | 64 MiB, 512 entries |

## The two hosts

| | Cabinet (`internal/cartridge/wasm`) | Browser host |
| --- | --- | --- |
| Runtime | wazero v1.10.1, pure Go (JIT on arm64) | native `WebAssembly.instantiate` |
| `host_blit` | engine framebuffer/layers | `putImageData` on a 64×64 canvas, `image-rendering: pixelated` |
| audio | engine `audio.Service` | WebAudio buffers from the bundle's WAVs |
| storage | engine `storage.Store` (disk) | `localStorage`, keyed `arkade/<slug>/<key>` |
| input | HID controllers + terminal keyboard | keyboard + Gamepad API + on-page controls |
| strategy / rotation / raw dirs | real | ported: the same gate, frame rotation and direction remap |
| attract | dedicated instance, `cart_init` + `cart_attract` + `cart_teardown` only | never called |
| unload | `module.Close()`; hot-swap via fsnotify on the cartridge dirs | page lifecycle |

Both hosts pin their agreement with the shared golden files — a
divergence is a host bug, and the fix is never to fork the goldens.
